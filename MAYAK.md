# Яндекс Маяк (ветка `ya`)

Отдельное приложение рядом с «Маяком» на VK-звонках: тот же принцип, но трафик
идёт через документ-транспорт OpenFlux (Yandex Docs, Mail.ru Docs, Cups.online).

Это изменённая копия [damnurmum/OpenFlux-Android](https://github.com/damnurmum/OpenFlux-Android)
(релиз v1.1.4, коммит `d821928`), ядро - [p1neappleXpress/OpenFlux](https://github.com/p1neappleXpress/OpenFlux)
(сабмодуль `core/`). Лицензия та же: GPL-3.0-or-later, см. `LICENSE`, `COPYRIGHT`, `NOTICE`.
Приложение не связано с Яндексом и Mail.ru и ими не одобрено.

## Что изменено относительно OpenFlux-Android v1.1.4 (2026-10-11)

- имя приложения и свой идентификатор пакета `ru.mayak.ya`, поэтому оно ставится
  рядом с OpenFlux и с «Маяком» и не обновляет их;
- свой значок;
- отключена проверка обновлений по релизам OpenFlux-Android (они не могут обновить
  это приложение);
- сборка: `.github/workflows/build-ya.yml` собирает подписанные APK при каждом
  коммите в ветку `ya` и публикует их пре-релизом `ya-build-N`;
- удалены workflow, шаблоны issue и PR исходного репозитория.
- ядро (`core/`): патчи из `patches/core-*.patch` накладываются при сборке;
  `core-0001` - мастер установки ноды показывает, что именно ответил сервер,
  когда скрипт установки не дал ответа (раньше текст ошибки был пустым).
  `core-0002` - мастер проверяет SSH-соединение перед каждым шагом и открывает
  его заново, если Android его оборвал (адрес и пароль для этого держатся в
  памяти, пока мастер подключён, и нигде не сохраняются).
  `core-0003` - один канал может идти сразу через несколько документов Яндекса
  (до 8): мастер принимает несколько ссылок, ядро делит между документами
  соединения. Для этого мастер запускает на сервере свою копию скрипта
  установки, `deploy/node-install.sh` из этой ветки (исходный скрипт
  p1neappleXpress/OpenFlux с добавленной поддержкой нескольких `vyandex=`),
  по закреплённому коммиту и SHA-256. Ядро ноды скрипт по-прежнему скачивает
  из релизов p1neappleXpress/OpenFlux.
  `core-0004` - необязательный режим L3 для нового канала (плитка «Режим L3»
  в мастере): нода пересылает сырые пакеты вместо обычного L4. Скрипт
  установки для этого даёт службе канала CAP_NET_RAW и добавляет правило
  iptables, гасящее исходящие RST всего сервера, поэтому режим рассчитан на
  сервер, где больше ничего не работает.
  `core-0005` - после «Проверить сервер» мастер показывает каналы, которые уже
  есть на сервере (порт, число документов, режим), и для каждого даёт
  переключатель L3/L4 без переустановки канала и замер скорости через
  документы (несколько секунд скачивания с speed.cloudflare.com в четыре
  соединения, без прямого подключения).

Протокол, транспорты, мастер установки ноды и формат ссылок `openflux://` не
менялись: приложение совместимо с нодами и ссылками OpenFlux.

## Сборка

Как в исходном репозитории (`README.ru.md`, раздел про сборку Android-приложения).
Номер сборки берётся из переменной `MAYAK_BUILD_NUMBER`. Про подпись - `ci/README.md`.
